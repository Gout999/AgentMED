# T6c 泛化用例设计（T6b 闭环收口后执行）

## 目的
证明 CaseLoop 不是"B1 专用剧本"：换措辞、换故障层，同一套团队+工具+流程仍能走通质量治理闭环。
判定标准：①走完闭环（立案→分诊→取证→归因→修复候选→门禁→人工批准→灰度→回复→归档→记账）；
②无剧本复读（agent 输出引用本案实时证据，不复述 B1 案例话术）。

## 用例 A：训练外措辞 × 同 B1 故障（表层泛化）

- **故障**：B1 已注入（维持现状，prompt_digest=81122ca0…）
- **投诉措辞**（全新，不含"退货/政策/激活"关键词组合）：
  「你们客服到底靠不靠谱？昨天下单前明明说可以的，今天就不认账了，截图我都有。这不是骗人吗？」
- **观察点**：
  - 质量官分诊是否仍定位到应用质量事件（措辞无"退货政策"直述，需要从"昨天可以今天不认账"推断答复一致性问题）
  - 采集员取证是否复用 app.logs digest 分组方法
  - 归因师是否直接走 5-cell（probe_set 应为本案新措辞构造的探针，不是 T6b 的探针原文）
- **反剧本关键**：若 agent 输出出现 T6b 案件的 case_id/探针原文/取证结论复述 → 判定剧本复读，泛化失败

## 用例 B：未见故障层 × B2 KB 回归（结构泛化）

- **前置**：先 `bash demo-app/scripts/reset_state.sh` 恢复基线，再注入 B2：
  `curl -X POST http://127.0.0.1:8080/admin/inject/B2 -H "Authorization: Bearer conformance-write-token"`
  （B2：KB 条目 X200 续航 30h→8h，kb_manifest_digest 漂移，prompt/model digest 不变）
- **投诉措辞**：「商品页写 X200 续航 30 小时，你们客服跟我说只有 8 小时？页面和客服总有一个在撒谎吧」
- **观察点**：
  - 采集员取证：digest 分组应出现在 **kb_manifest_digest**（而非 prompt_digest）——分层归因的判别力
  - 归因师 5-cell 假设层应为 kb（不是 prompt）；若仍假设 prompt → 层间泛化失败
  - 修复师候选 WorkOrder 应指向 KB 条目回滚（不是 prompt 模板）
- **收尾**：测完必须 reset_state.sh 恢复基线

## 执行纪律（同 T6b）
- RPM=10 串行；人工只在门禁批准点介入（纠偏次数本身计入泛化评价：纠偏越少=泛化越好）
- 每用例证据落 evidence/phase1/t6c-{a,b}-*.md（房间日志导出 + 控制面事件流 + 裁决报告）
- 两个用例串行执行（共享同一 StepFun 配额 + 同一 demo-app 故障态）

## 通过线
- A：闭环走通 + 零剧本复读 + 纠偏≤2 次
- B：归因层正确=kb + 闭环走通 + 纠偏≤2 次
- 任一失败 → 失败模式入 evidence，修复后重测（泛化是终考，不通过不演示）
